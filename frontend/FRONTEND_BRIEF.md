# 🎨 Frontend Developer Guide & Requirements

Welcome to the frontend! Your core mission for this 24-hour hackathon is to build a sleek, professional, and highly responsive UI that wows the judges. You don't need to worry about the AI, database, or cryptography—the backend handles all of that. 

Your goal is **speed and aesthetics**.

---

## 🛠️ The Tech Stack

You must stick to these tools to ensure we move fast:
*   **Framework:** React 18 + Vite (Lightning-fast builds).
*   **Routing:** React Router v6 (For navigating between pages).
*   **Styling:** Tailwind CSS (No custom CSS files, use utility classes to save time).
*   **Components:** `shadcn/ui` (Highly recommended to copy-paste pre-built tables, modals, and buttons) or just raw Tailwind.
*   **Icons:** Lucide React (`npm install lucide-react`).
*   **API Calls:** Standard `fetch()` or `axios`.

---

## 📄 Pages You Need to Build

Here is the exact checklist of pages to create:

### 1. Landing Page (Public)
*   **Purpose:** The "hook" for the judges. Needs to look like a modern GovTech startup.
*   **Content:** Hero section explaining the value (e.g., "AI-Powered Tender Verification in Minutes, Not Days").
*   **Actions:** Two main buttons: "Apply as Bidder" and "Officer Login".

### 2. Bidder Registration Page (Public)
*   **Purpose:** Where external companies apply for a tender.
*   **UI Elements:** 
    *   Form: Company Name, Registration Number (PAN/GST), Tender ID.
    *   File Upload: A drag-and-drop zone for PDF/Images. 
*   **⚠️ Hackathon Shortcut:** Don't build a complex AWS/Supabase file upload logic yet! Just make the UI *look* like it uploads, show a fake progress bar, and send a hardcoded dummy image URL to the backend.

### 3. Officer Login Screen (Public)
*   **Purpose:** Standard email/password login for Procurement Officers.
*   **UI Elements:** Simple card with Email, Password, and a "Secure Login" button.

### 4. Procurement Officer Dashboard (Private / Protected)
*   *This is the star of the show. Spend 60% of your time here.*
*   **Purpose:** The command center for the officer to view and verify bids.
*   **UI Elements:**
    *   **Data Table:** A list of all bidders showing their Name, ID, and Status (`Pending`, `Verified`, `Rejected`).
    *   **The "Verify" Button:** Next to pending bids. Clicking this shows a loading spinner (simulating the AI working) and calls the backend.
    *   **Risk Score Badge:** Once verified, display the AI's risk score (e.g., Green for Low Risk, Red for High Risk).

### 5. Audit Trail View (Private)
*   **Purpose:** Proves to the judges our security is unbreakable.
*   **UI Elements:** A timeline or table showing the history of actions. Must include a column displaying the **Cryptographic SHA-256 Hash** generated by the backend.

## 🔌 The API Contract (How you talk to the Backend)

**CRITICAL RULE:** Do not wait for the backend to be finished! Hardcode dummy data in your React components (`useState`) so you can design the UI immediately. Once the backend is ready, swap the dummy data with these API calls:

**1. Submit a Bid:**
*   `POST http://localhost:5000/api/bids`
*   You send: `{ companyName: "TechCorp", taxId: "12345", documentUrl: "dummy.pdf" }`

**2. Fetch Dashboard Data:**
*   `GET http://localhost:5000/api/bids`
*   You receive: `[{ id: 1, companyName: "TechCorp", status: "pending", riskScore: null }]`

**3. Run AI Verification:**
*   `POST http://localhost:5000/api/verify`
*   You send: `{ bidId: 1 }`
*   You receive: `{ status: "verified", riskScore: 85, aiAnalysis: "Tampering detected in font sizing." }`

## 💡 Pro-Tips for the Hackathon
1.  **Fake it till you make it:** If an API endpoint isn't ready, just `setTimeout` for 2 seconds and resolve dummy data so you can keep building the UI.
2.  **Make it flashy:** Add loading spinners when buttons are clicked. AI takes time to process, and a good loading state builds suspense for the judges.
3.  **CORS:** If your `fetch` calls are blocked, tell the Backend Developer to `npm install cors` and enable it in their Express app.
